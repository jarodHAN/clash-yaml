# 2026-10-11

## 自建 macOS Clash 客户端（clashVPN）
- 起因：用户查 github.com/kr328 是否有 macOS Clash 应用 —— 结论：无（仅 Android/Linux，ClashForAndroid 已 404，clash-premium-installer 已弃用）。
- 方案：用 **mihomo（clash-meta）v1.19.32 darwin-amd64** 作为核心，自建 SwiftUI 菜单栏 App（无 Xcode 工程，swiftc 直接编译 + 手动组装 .app）。
- 关键事实/坑：
  - swiftc 必须带 `-sdk $(xcrun --show-sdk-path)` 否则报 "unable to load standard library"。
  - NSImage 在此 SDK 只能用 `init(systemSymbolName:accessibilityDescription:)`（无 pointSize 版本）。
  - mihomo 外部控制器：**节点选择用 `PUT /proxies/{name}`，模式切换用 `PATCH /configs`**（用 PUT 会静默无效果）。
  - mihomo 启动依赖 geo 数据库（geoip.metadb）；GitHub 的 meta-rules-dat 在此环境/中国网络常不可达 → 默认配置改为**仅域名规则分流**（DOMAIN-SUFFIX/KEYWORD,cn,DIRECT + MATCH,PROXY），不强制依赖 GEOIP；仅有 geoip.metadb 时才加 GEOIP 规则。
  - 菜单栏 App：用 NSStatusItem + NSPopover + NSHostingController，**不**用 App 宏/MenuBarExtra，避免 SwiftPM 资源与 .app 组装复杂度。
- 产物：`build/clashVPN.app`（x86_64，ad-hoc 签名，内嵌 mihomo）。运行 `open build/clashVPN.app`；首次需允许未签名 mihomo（系统设置→隐私与安全）。系统代理通过 `networksetup` + osascript 提权设置。
- 约束：仅 Intel Mac（x86_64）；关闭 App Sandbox；正式分发需付费 Apple Developer 账号。

## 第二期增强（订阅 + 节点测速 UI）
- 订阅加载修正：原先用 `profile:` 配置块**不会**把节点并入 PROXY 组。改用标准 mihomo **`proxy-providers` + 组 `use:`** 模式（provider 名 `sub`，`type: http`，`interval: 3600` 即定时更新），PROXY 组的 `all` 才会出现订阅节点。已用本机 http server 起最小订阅文件端到端验证：节点正常载入、`PUT /providers/proxies/sub` 返回 204、节点选择生效。
- 订阅持久化：订阅 URL 存 `UserDefaults`（key `clashVPN.subscriptionURL`），重启后自动回填。
- 订阅更新 UI：新增「更新」按钮 → `ClashController.updateSubscription()`（先 `GET /providers/proxies` 找 vehicleType=HTTP / 名 sub 的 provider，再 `PUT /providers/proxies/{name}`）；另在 connect() 里加 15s `Timer` 轮询 `refreshProxies()`，使 mihomo 自动刷新后的节点在 UI 出现。
- 节点/测速 UI 增强：`GroupRow` 由菜单式 Picker 改为**可点击节点列表**，逐节点显示延迟并颜色分级（<150ms 绿、<300ms 黄、≥300ms 橙、超时红）；新增「测速」按钮（`testAll` 对组内每个节点调 `proxies/{name}/delay`）和顶部「测速全部」。延迟存于 `AppState.delayMap`（key `group|node`，超时记 -1）。
- geo 数据库本次成功下载并入包（`Resources/geo/geoip.metadb` + `geosite.dat`），故 GEOIP 规则现在也会启用。
- 构建：`build.sh` 不变；产物仍是 `build/clashVPN.app`。
